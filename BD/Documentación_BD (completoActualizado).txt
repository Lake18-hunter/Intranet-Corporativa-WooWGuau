1. CONFIGURACIÓN DE LA BASE DE DATOS

Motor de BD: MySQL Server 8.0 (InnoDB)
Juego de caracteres: utf8mb4_spanish_ci

Por qué se configuró así:
* Motor InnoDB: Soporta llaves foráneas (FOREIGN KEY) y transacciones seguras para que no se corrompan los datos.
* Cotejamiento utf8mb4_spanish_ci: Acepta acentos y ñ sin problemas y no distingue entre mayúsculas y minúsculas al buscar.
* Normalización en 3FN: Separa los catálogos (tipos_especie, categorias_producto, marcas_comerciales) de las tablas donde se mueven los datos del día a día.
* Lista para Azure: Es 100% compatible con Microsoft Azure Database for MySQL.


2. DICCIONARIO DE DATOS (17 TABLAS)

--- SEGURIDAD Y EXPEDIENTES ---

TABLA: roles_usuario
- id_rol (INT, NOT NULL, PK, AUTO_INCREMENT): Identificador único del rol.
- nombre_rol (VARCHAR(30), NOT NULL, UNIQUE): Nombre del rol ('Administrador', 'Gerente', 'Empleado').
- descripcion_rol (VARCHAR(150), NULL): Descripción de los permisos.
- fecha_registro (DATETIME, DEFAULT CURRENT_TIMESTAMP): Fecha de creación.

TABLA: usuarios_sistema
- id_usuario (INT, NOT NULL, PK, AUTO_INCREMENT): Identificador único de usuario.
- nombre_usuario (VARCHAR(50), NOT NULL, UNIQUE): Nombre para iniciar sesión.
- correo (VARCHAR(100), NOT NULL, UNIQUE): Correo de contacto (cuentas Gmail).
- hash_contrasena (VARCHAR(255), NOT NULL): Clave de acceso encriptada (hash).
- id_rol (INT, NOT NULL, FK -> roles_usuario): Rol asignado.
- estatus_cuenta (TINYINT(1), DEFAULT 1): Estado (1 = Activa, 0 = Inactiva).
- fecha_ultimo_acceso (DATETIME, NULL): Última vez que entró al sistema.
- fecha_alta (DATETIME, DEFAULT CURRENT_TIMESTAMP): Fecha de alta.
- fecha_modificacion (DATETIME, DEFAULT CURRENT_TIMESTAMP ON UPDATE): Última modificación.

TABLA: expediente_empleados
- id_empleado (INT, NOT NULL, PK, AUTO_INCREMENT): Identificador del expediente.
- id_usuario (INT, NULL, FK -> usuarios_sistema, UNIQUE): Enlace a su cuenta de acceso (puede quedar vacío si aún no tiene usuario).
- numero_empleado (VARCHAR(15), NOT NULL, UNIQUE): Código interno del trabajador.
- nombre_empleado (VARCHAR(50), NOT NULL): Nombre(s) del trabajador.
- apellido_paterno (VARCHAR(50), NOT NULL): Apellido paterno.
- apellido_materno (VARCHAR(50), NULL): Apellido materno.
- telefono_contacto (VARCHAR(15), NULL): Teléfono de contacto.
- puesto_trabajo (VARCHAR(50), NOT NULL): Puesto en la tienda.
- fecha_ingreso (DATE, NOT NULL): Fecha de contratación.
- estatus_laboral (ENUM('Activo', 'Inactivo', 'Baja Logica'), DEFAULT 'Activo'): Estado laboral.
- fecha_alta (DATETIME, DEFAULT CURRENT_TIMESTAMP): Fecha de registro.
- fecha_modificacion (DATETIME, DEFAULT CURRENT_TIMESTAMP ON UPDATE): Última actualización.


--- CATÁLOGOS E INVENTARIO ---

TABLA: tipos_especie

- nombre_especie (VARCHAR(30), NOT NULL, UNIQUE): Nombre ('Perro', 'Gato', 'Multiespecie').

TABLA: categorias_producto
- id_categoria (INT, NOT NULL, PK, AUTO_INCREMENT): Identificador de la categoría.
- nombre_categoria (VARCHAR(50), NOT NULL, UNIQUE): Nombre ('Alimento Seco', 'Accesorios', etc.).

TABLA: marcas_comerciales

- nombre_marca (VARCHAR(50), NOT NULL, UNIQUE): Nombre comercial de la marca.

TABLA: inventario_productos
- id_producto (INT, NOT NULL, PK, AUTO_INCREMENT): Identificador del producto.
- codigo_sku (VARCHAR(30), NOT NULL, UNIQUE): Código SKU único.

- descripcion_producto (TEXT, NULL): Descripción detallada.

- id_especie (INT, NOT NULL, FK -> tipos_especie): Referencia a especie.
- id_categoria (INT, NOT NULL, FK -> categorias_producto): Referencia a categoría.
- id_marca (INT, NOT NULL, FK -> marcas_comerciales): Referencia a marca.
- estatus_producto (TINYINT(1), DEFAULT 1): Estado (1 = Activo, 0 = Inactivo).
- fecha_alta (DATETIME, DEFAULT CURRENT_TIMESTAMP): Fecha de registro.
- fecha_modificacion (DATETIME, DEFAULT CURRENT_TIMESTAMP ON UPDATE): Última actualización.

3. REGLAS DE INTEGRIDAD Y RESTRICCIONES

1. Llaves foráneas con ON DELETE RESTRICT ON UPDATE CASCADE: Impiden borrar roles, usuarios, proveedores, especies, categorías o marcas que ya estén en uso.
2. fk_empleados_usuarios con ON DELETE SET NULL ON UPDATE CASCADE: Si se borra la cuenta de usuario, el expediente del trabajador no se pierde.
3. Borrado en cascada (ON DELETE CASCADE): Solo se usa en tablas dependientes como detalle_orden_compra, horarios_empleado, asistencias e incidencias_laborales si se llega a eliminar el registro principal.
4. Validaciones CHECK en inventario y precios: Impiden guardar stock_actual, stock_minimo, precio_publico o costo_unitario con números negativos.
5. Validaciones CHECK en movimientos y cortes: Obligan a que cantidad sea mayor a 0, que toda 'Venta' tenga precio_unitario, y que ningún corte o incidente marcado como revisado quede sin fecha de revisión.
6. Llaves únicas (UNIQUE): Evitan duplicar horarios el mismo día para un empleado, pasar dos veces asistencia en la misma fecha o abrir dos cortes de caja el mismo día.
7. Baja lógica: Se usa ENUM('Activo', 'Inactivo', 'Baja Logica') en expediente_empleados y banderas TINYINT(1) (1 = Activo, 0 = Inactivo) en cuentas, productos y proveedores para no borrar datos históricos.
